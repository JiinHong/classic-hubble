# 클래식허블 검색 중심 UI

날짜: 2026-11-02
상태: 1번 방향 승인, 문서 검토 대기

## 목표

첫 화면을 공연 데이터 현황판에서 곡명으로 공연을 찾는 검색 화면으로 바꾼다.
ChatGPT와 Gemini의 입력 중심 구성을 참고하되, 채팅이나 AI 답변 기능을 추가하지 않는다.
사용자는 1번인 '자동완성 후 선택 또는 Enter로 결과 표시' 방식을 선택했다.

## 첫 화면

- 흰색 바탕, 어두운 본문, 중립적인 회색 경계선, 작은 초록색 강조를 사용한다.
- 상단에는 작은 클래식허블 로고, 보조 메뉴, 로그인 또는 계정 버튼을 둔다.
- 작곡가와 관심곡은 키보드로도 접근 가능한 보조 메뉴에 둔다.
- 검수 링크는 일반 탐색 메뉴에서 제거한다. 관리 경로와 권한 검사는 유지한다.
- 중앙에는 '클래식허블' 제목과 검색창만 둔다. 입력 힌트는 '곡명, 작곡가, 별칭'이다.
- 유튜브 검색은 검색창에 인접한 작은 아이콘 링크로 유지한다. 이름과 툴팁을 제공한다.
- 등록된 공연, 작품 수, 곡목 확인 수, 프로그램 확인 중, 가까운 공연,
  곧 열리는 주요 공연, 검색 전 기본 작품 목록, 바로 찾기 예시 버튼을 제거한다.
- 일반 홈페이지 방문에서는 작품 목록, 공연 목록, 통계 조회를 실행하지 않는다.
  로그인 상태 조회는 이 카탈로그 조회 제한과 구분한다.
- 출처와 라이선스 링크는 간결한 하단 영역에 유지한다. 필수 출처 표시는 삭제하지 않는다.

## 검색 흐름

1. 검색창에 입력하면 추천 목록만 검색창 아래에 표시한다. 전체 결과는 바뀌지 않는다.
2. 추천은 작품명과 작곡가를 포함한 최대 8개의 짧은 행으로 표시한다.
3. 작품 추천을 선택하면 해당 작품을 선택한 결과 화면으로 전환한다.
   명확한 작품 식별자를 전달하며, 표시 문구를 다시 일반 검색해 다른 작품을 고르지 않는다.
   해당 작품과 연결된 예정 공연을 보여주고 작품 상세로 이동할 수 있게 한다.
4. 추천을 선택하지 않고 Enter 또는 검색 아이콘을 누르면 기존 규칙으로 전체 검색한다.
   결과 화면에서 작품/공연 전환, 공연 지역 선택, 더 보기를 사용할 수 있다.
5. 결과 화면에서는 검색창을 상단에 두고 목록을 아래에 표시한다.
   검색어를 편집하는 동안 이전 결과는 기존 확정 검색어의 결과로 구분해 유지한다.
   새 검색을 확정하면 결과를 교체하고 페이지 위치를 초기화한다.
6. 입력을 지우면 첫 화면으로 복귀하며 빈 검색어로 전체 목록을 조회하지 않는다.
7. 검색어와 선택한 작품 상태를 URL에 반영한다. 새로고침과 뒤로가기로 상태를 복원한다.
   기존 작곡가 페이지의 `?composer=` 진입도 유지한다.

## 자동완성과 조회

- Redis, Elasticsearch, 새 LLM 호출 없이 기존 PostgreSQL과 Next.js를 사용한다.
- 일반 결과 API와 추천 API를 분리한다. 추천에는 작품 식별자, 표시 제목, 작곡가만 반환한다.
  공연 상세, 연결 공연 수, 정확한 전체 검색 건수는 추천 단계에서 조회하지 않는다.
- 기존 정규화와 검증된 별칭, 줄임말을 재사용한다. `라흐 피협`, `브바협`, `운명`,
  작품 번호 검색은 회귀 검증 대상이다. 추천의 제한 때문에 정식 검색 결과를 잘라내지 않는다.
- 자동완성은 별도의 제한된 DB 조회 함수와 필요한 인덱스로 구현한다.
  전체 후보를 서버로 내려받은 뒤 8개만 반환하는 구현은 허용하지 않는다.
- 추천은 정규화 후 정확 일치, 접두 일치, 나머지 지원되는 별칭 일치 순으로 정렬한다.
  동률은 기존 인기 순위와 안정적인 식별자로 정렬하고 동일 작품은 중복 표시하지 않는다.
- 한두 글자 입력은 접두 검색을 사용한다. 짧은 부분 문자열로 전체 카탈로그를 훑지 않는다.
- 한글 조합 중에는 요청하지 않는다. 조합이 끝나거나 일반 입력이 멈춘 뒤 100ms 후 조회한다.
- 이전 요청을 취소하고 응답 순서를 확인한다. 오래된 응답이 최신 입력을 덮어쓰지 못하게 한다.
- 최근 추천은 브라우저에서 최대 20개 검색어, 60초 동안 재사용한다.
  서버에서도 기존 방식의 짧은 캐시를 사용한다. 전체 카탈로그 다운로드 fallback은 두지 않는다.
- DB 변경은 추천 함수와 인덱스를 추가하는 범위로 제한한다.
  작품, 작곡가, 공연 원본과 공개 연결을 수정하지 않는다.
- 대상 프로젝트는 `klnfamtwxwrelrjeguqb`만 사용하고 요금제를 바꾸지 않는다.

## 결과와 상세 페이지

- 검색 결과는 큰 장식 카드 대신 제목, 작곡가, 필요한 공연 정보를 읽기 쉬운 행으로 정리한다.
- 공연에는 기존 실제 포스터를 작은 고정 비율 이미지로 사용한다. 장식용 이미지를 추가하지 않는다.
- 작품 상세의 예정 공연과 과거/종료 공연 구분, 구성곡 관계, 관심곡 기능을 유지한다.
- 공연 상세의 포스터, 일시, 장소, 출연, 프로그램, 예매 링크를 유지한다.
- 상세 페이지의 큰 외곽 카드, 중첩 카드, 불필요한 그림자와 통계성 요약은 정리한다.
  출처와 프로그램 확정 여부, 악장/발췌 범위 등 사실 확인에 필요한 정보는 삭제하지 않는다.
- 공통 헤더와 하단은 전체 사이트에 적용한다. 작곡가, 관심곡, 유튜브 페이지의 본문 기능은
  이번에 전면 재설계하지 않고 새 공통 스타일과의 충돌만 조정한다.
- 검수 시스템과 OCR/작품 매칭 작업은 이번 범위에 포함하지 않는다.

## 상태와 접근성

- 추천 입력창은 combobox, 추천 목록은 listbox와 option 의미를 제공한다.
- 위/아래 키로 이동, Enter로 선택 또는 검색, Escape로 닫기, 바깥 클릭으로 닫기를 지원한다.
  한글 입력을 확정하는 Enter는 검색 제출로 처리하지 않는다.
- 추천 조회 실패와 추천 없음, 전체 검색 실패와 결과 없음을 구분한다.
  추천 실패 시에도 일반 검색 제출은 가능하며 실패를 빈 결과로 표시하지 않는다.
- 로딩 중에도 입력과 화면 폭이 흔들리지 않는다. 검색 결과 오류에는 재시도를 제공한다.
- 모바일 키보드가 열려도 입력창과 추천 목록이 접근 가능해야 한다.
  긴 곡명은 줄바꿈하고 가로 스크롤이나 버튼 겹침이 없어야 한다.
- 아이콘 버튼에 접근 가능한 이름과 툴팁을 제공한다. 움직임 감소 설정을 존중한다.

## 구현 경계

- `AppHeader`, `SiteFooter`, 공통 스타일: 최소한의 탐색과 시각 체계.
- 홈페이지: 빈 검색 화면과 URL 기반 진입을 구분하며 불필요한 초기 DB 조회를 제거.
- 자동완성 컴포넌트: 입력, 한글 조합, 추천 선택, 요청 순서, 캐시, 키보드 동작.
- 검색 결과 컴포넌트: 확정된 검색어, 모드/지역, 페이지 조회와 기존 매칭 결과 표시.
- 추천 조회 모듈/API/SQL: 제한된 데이터 계약과 조회만 담당.
- 작품/공연 상세와 반복 결과 행: 기존 정보와 링크를 유지하면서 표시를 단순화.

기존 전체 카탈로그 조회 제거 작업 `92f2792` / PR 111 위에서 진행한다.
UI 브랜치는 해당 커밋을 기반으로 별도 생성했으며 기존 PR을 수정하지 않는다.
운영 반영 전 PR 111의 병합 상태를 확인하고 중복 커밋이 포함되지 않도록 정리한다.
기존 OCR 관련 dirty 파일과 미완성 migration은 변경하거나 커밋하지 않는다.

## 검증 기준

- 첫 화면에서 제거 대상 문구와 기본 작품/공연 목록이 보이지 않는다.
- 빈 홈페이지에서 작품/공연/통계 조회가 발생하지 않는 테스트를 추가한다.
- 추천 응답은 최대 8개이고 상세 공연 및 전체 건수 조회가 없음을 검증한다.
- 별칭/줄임말, 동명이곡 구분, 추천 선택의 식별자 전달, 정식 검색 결과의 기존 순서를 검증한다.
- 키보드, 한글 조합, 연속 입력, 요청 실패, 캐시 만료, URL 복원, 페이지 추가를 테스트한다.
- 예정/과거 공연, 프로그램 범위와 출처, 관심곡, 로그인, 예매 링크의 회귀 테스트를 수행한다.
- 데스크톱과 모바일에서 실제 브라우저로 첫 화면, 추천, 결과, 두 상세 페이지를 확인한다.
- 입력부터 추천이 화면에 표시되기까지의 시간과 추천 요청의 응답량을 측정한다.
  최초 요청과 캐시 적중을 구분하며 측정 전 속도를 보장하지 않는다.
- 타입 검사, 린트, 관련 테스트와 빌드를 통과한 뒤 변경 내용을 검토한다.
- 로컬 실행 주소를 제공하고 운영 배포 여부는 별도로 명시한다.
